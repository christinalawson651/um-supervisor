Audit & Traceability

Proving who did what, when, from where — and that the record has not changed since. Across utilization management, care management and appeals, including the decisions a model influenced.

Two things get called “audit”

They need different evidence, and conflating them is how an audit conversation goes wrong. Both are in the platform.

Clinical quality audit

“Did the reviewer apply the criteria correctly?”

Evidence: inter-rater reliability against an independent re-determination, documentation file review, regulatory turnaround by program.

Asked by: NCQA and URAC surveyors, delegation-oversight clinicians.

System audit & traceability

“Who did what, when, from where — and is the record unaltered?”

Evidence: hash-chained event log, user activity review, access governance, model oversight, retention and disposition.

Asked by: CMS program audit, HIPAA security review, SOC 2, plan IT security.

The part that matters to an auditor A configuration change is not a quiet edit. Publishing one writes an event carrying the field, the value before and after, the person, and the change ticket — and it is checked for an independent approval by someone other than the publisher. A criteria set, a letter template, a turnaround window, a role entitlement and a model version are all governed the same way, because each of them silently rewrites how every subsequent case is decided.

Direction  Configuration is versioned data today, changed through governed release. The roadmap is a headless rules runtime with an authoring portal, so a compliance or clinical-content owner edits a threshold or a rubric directly — under the same versioning, approval and audit-logging the platform already applies.
